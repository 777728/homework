### 为什么动画在浏览器里重放

源码是 C/C++，无法直接在页面里逐语句执行。做法是**把同一套语句顺序在 JS 里重放**：
每一步只记录「执行到哪一行 + 当时的数据结构快照」，渲染器只负责画快照。
这样既能做到行级高亮，又不需要给 C 程序加插桩、改编译参数，页面依旧零构建、零打包。

## 三、核心机制

### 3.1 步骤模型

```js
{
  file: 'src/lab1/Polynominal.cpp',  // 源码文件（决定右侧切到哪个标签）
  line: 119,                          // 要高的行号（与真实文件一致）
  desc: 'pre->next 的指数 6 > 3，pre 继续后移',
  state: { A: [...], B: [...], R: [...], pa: 1, pb: 0, insPre: 0 },
  hold: 1                             // 关键步骤停留更久（倍数）
}
```

### 3.2 播放器

- 基础间隔 520 ms，速度 0.4×–3×（默认 1.15×）；
- 播到末尾自动回到第 0 步（`loop` 默认开启）；
- 进度条可点击跳转，`←/→` 单步，`空格` 暂停，`F` 全屏。

```js
seek(i) {
  const step = this.steps[i];
  this.onStep(step, i);                 // 切源码文件 + 高亮 + 重绘
  if (this.playing) {
    const delay = Math.max(60, BASE_MS * (step.hold || 1) / this.speed);
    this.timer = setTimeout(() => {
      if (this.index >= this.steps.length - 1) {
        if (this.loop) { this.index = -1; this.step(); } else this.pause();
      } else this.step();
    }, delay);
  }
}
```

### 3.3 源码面板

- `show(keyOrPath)` 同时接受文件 key 与源码路径（步骤里带的是路径）；
- 源码只渲染一次（按行生成 `div.code-row`，`data-line` 存行号）；
- 高亮时把目标行滚到面板 42% 处：
  ```js
  const top = row.offsetTop - this.scroll.clientHeight * 0.42;
  this.scroll.scrollTop = clamp(top, 0, this.scroll.scrollHeight);
  ```
  （`.code-scroll` 设 `position: relative`，`offsetTop` 才相对滚动容器。）

### 3.4 人工代码标注

`annotations.js` 以「函数起止行」为单位标注，渲染时给区间内的行加左边色条与类名，
并在函数首行插入一条说明：

```js
'src/lab1/Polynominal.cpp': [
  { from: 116, to: 144, kind: 'core',   label: 'InsertInOrder 按指数降序插入 / 合并同类项' },
  { from: 155, to: 188, kind: 'helper', label: 'PrintPolyn 输出格式' },
  ...
]
```

| 颜色 | 含义 | 举例 |
| --- | --- | --- |
| 绿 | 人工编写的核心算法 | `AddPolyn`、`MazePath`、`Select`、`dijkstra` |
| 灰 | 人工编写的配套代码 | 输入解析、打印、菜单、销毁 |
| 黄 | 人工整理的数据 | `CampusData.cpp` 的 22 点 46 边 |

面板底部同时显示文件路径、总行数与「人工编写 N 行」，便于答辩时说明工作量。

## 四、四个实验的动画设计

| 实验 | 视图 | 步骤数 | 关键源码行 |
| --- | --- | --- | --- |
| 一 · 多项式 | 三条链表（A / B / psum）+ 指针 | 84 | `InsertInOrder` 118–139、`AddPolyn` 190–226 |
| 一 · 高斯消元 | 增广矩阵 + 行号 + 主元框 | 65 | `SolveLinearSystem` 21–75 |
| 二 · 迷宫 | 11×15 迷宫 + 链表栈面板 | 273 | `MazePath` 25–63 |
| 三 · 二叉树 | 层序布局的二叉树 + 递归栈 | 105 | `CreateBiTree` 5–13、`PreOrder` 22–27 |
| 三 · 哈夫曼 | 森林 + 静态数组表 + 编码表 | 103 | `Select` 6–13、`CreateHuffmanTree` 24–31、`HuffmanCoding` 37–47 |
| 四 · 最短路径 | 3D 校园 + 浮标 + 路径流光 | 86 | `dijkstra` 65–110 |
| 四 · 深度优先 | 3D 校园 + 访问序列 | 142 | `depthFirstTraversal` 21–42 |

### 4.1 多项式：把「指针走位」画出来

- 建 A、B 时每一步都走 `InsertInOrder`，指针 `pre` 用红色三角标在结果链表下方；
- 归并阶段三条链表并排，`pa/pb` 落在当前比较的结点上，气泡里显示 `3x^6 vs 4x^6`；
- 系数相加为 0 时，结点变红并被删除，旁注「链表里不留零项」；
- 结束后给出 `psum = 7x^6 + 7x − 4`，行尾持续显示各表表达式与表长。

### 4.2 高斯消元：单元格级步进

- 选主元时逐格扫描并比较绝对值（高亮当前格，标出当前最大）；
- 换行、归一化、消元都拆到「单个元素」一级，例如
  `M[2][1] -= 2 × M[1][1] → -2.333`；
- 蓝色虚线框标出主元位置，虚线分隔常数列，左上角实时显示当前行变换 `R2 − 2·R1`。

### 4.3 迷宫：栈的内容与格子状态同步

- 迷宫用「奇数坐标挖洞」的递归回溯生成，固定种子保证每次刷新同一张图；
- 格子状态：`0 通路 / 1 墙 / 2 足迹 / 3 死路 / 4 最终路径`；
- 右侧链表栈逐项显示 `#step (r,c) d方向`，栈顶高亮并带 `top` 指针；
- 回溯时逐格标 `×`，`curstep` 同步回退，能直观看到「四个方向都试过才判死」。

### 4.4 二叉树 / 哈夫曼

- 建树时按 `s[idx++]` 逐个字符演示，`#` 明确提示「空子树」；
- 递归遍历把「进入 / 访问 / 深入左 / 深入右 / 返回」都单独成步，左下角画出递归栈；
- 树布局用「叶子占格、父结点居中于子结点」的方式，避免中序布局把根挤到一角；
- 哈夫曼建树过程中画的是**森林**（`parent == 0` 的子树各自成树），
  右侧静态数组同步高亮 `s1 / s2 / 扫描位置`，最后从叶子回溯出 0/1 编码。

### 5.5 算法与 3D 联动

```js
// 每步都把快照刷到场景
scene.resetNodes();
for (let v = 0; v < 22; v++) if (s.done[v]) scene.setNodeState(v, 'settled');
s.path.forEach(v => scene.setNodeState(v, 'path'));
if (s.cur != null) scene.setNodeState(s.cur, 'current');
if (s.activeEdge) scene.setEdgeState(s.activeEdge[0], s.activeEdge[1], 'active');
scene.setPath(s.path);         // 路径用 CatmullRom 管道 + 沿路移动的“校车”
```

- 顶点状态：白/待定 → 琥珀/在堆 → 蓝/已确定 → 红/当前 → 金/最终路径；
- 每个顶点上方悬浮一个八面体浮标 + 一根细光柱，避免被屋顶挡住；
- 右侧源码同步高亮 `pq.pop / 松弛 / prev 回溯 / reverse` 等行；
- 步骤说明里带上距离，例如「邻点 15『桦苑』：w(21,15) = 400 米」。

### 5.6 交互

## 六、服务端改动

`webui.c` 原本把 `web/index.html` 整页读进 256 KB 缓冲区。页面拆分后需要静态托管，
于是把「首页分支」换成通用静态文件服务，并保留 `/api`：

```c
static const char *MimeType(const char *path);          // html/css/js/json/cpp/svg/jpg…
static int SafePath(const char *url);                   // 只允许字母数字 - _ . /，拒绝 ".."
static void SendFile(sock_t fd, FILE *fp, const char *type, long size);  // 16 KB 分块发送
static int ServeStatic(sock_t fd, const char *url) {
    char rel[512];
    if (!SafePath(url)) goto not_found;
    if (strcmp(url, "/") == 0) snprintf(rel, sizeof rel, "%s/index.html", WEB_ROOT);
    else                       snprintf(rel, sizeof rel, "%s%s", WEB_ROOT, url);
    FILE *fp = fopen(rel, "rb");
    ...
}
```

- 请求分发改为：`GET → ServeStatic`，`POST /api → 原有四个实验的计算入口`；
- 编译仍为 `cc -std=c11 -Wall -Wextra -O2`，**零警告**；
- 页面不再依赖任何外部 CDN：three.js r160 放在 `web/vendor/`，源码在 `web/src/`。

## 九、取舍与后续

1. **动画是重放而非插桩**：行级高亮需要「执行到哪一行」，给 C 程序加 trace 会污染源码；
   重放保留了源码原貌，代价是算法有两份实现（C/C++ 与 JS），已通过同数据、同步数核对。
2. **3D 是教学示意，不是测绘**：建筑体量、道路长度按公开资料与示意图估算；
   若课程要求精确，可只改 `campus-data.js` 的坐标与 `CampusData.cpp` 的权值。
3. 顶点仍用 lab4 的 22 点（未加入泽湖、钟楼等景物为图顶点），这样 Dijkstra 的结果与源码一致；
   景物只作场景装饰与地名标注。
4. 若要扩展到实验五、六（树/图之外的原有 C 模块），复用 `mountLab` 与步骤模型即可，
